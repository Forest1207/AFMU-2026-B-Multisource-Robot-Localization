# 问题四：固定轨迹上的连续可行窗口与联合任务优化

本目录在问题三正式 10 Hz 轨迹上完成：

```text
Q3 融合轨迹 + 18 个射击目标 + 18 个拍照目标
  → 每个 0.1 s 执行时刻的完整准备窗检查
  → 参考包式候选压缩（拍照 5° 方位角箱）
  → PCHIP 状态在 0.01 s 网格连续复核
  → 三阶段字典序 MILP
  → 每个入选任务 ±0.1 s 连续时间裕度精修
  → 两位小数时刻再次 0.01 s 复核
  → result.xlsx 向下扩展写入全部任务并保护红色说明区域
```

## 关键更正：模板 9 行不是任务容量

题目只要求将任务结果填入 `result.xlsx` 且不改变红色文字，并没有规定“最多只能执行 9 项任务”。模板中已有 9 条空白编号仅作为初始填写区域，不能转化为优化模型的容量约束。

因此正式模型：

- **不设置 `sum x <= 9`；**
- **不把 1.5 s / 0.5 s 准备区间解释为跨任务互斥资源；**
- `result.xlsx` 在 A:E 区域按最终任务数向下扩展；
- H:L 红色说明/范例以及原表头保持不变。

这一口径与参考提交包的 Q4 实现一致。

## 题设硬约束

### 射击

执行前 1.5 s 的完整准备窗口内持续满足：

- `5 <= d <= 30 m`；
- `v <= 2 m/s`；
- `a <= 1.5 m/s²`。

同一个射击目标至多计一次射击任务。单次命中率 0.85 用于报告期望命中数。

### 拍照

执行前 0.5 s 的完整准备窗口内持续满足：

- `10 <= d <= 40 m`；
- `v <= 1.5 m/s`；
- `a <= 1.5 m/s²`。

同一目标可以拍摄多张照片，但任意两张入选照片的圆周最小方位角差必须至少为 `60°`。

## 三阶段字典序 MILP

设候选任务变量为 `x_e`，目标覆盖变量为 `y_g`。

### Level 1：最大化目标覆盖数

```math
\max \sum_g y_g
```

这里的“覆盖”按 `(任务类型, 目标编号)` 计数。例如拍照目标 P01 只要至少有一张有效照片就贡献一个一级覆盖目标；额外照片不增加一级目标值。

### Level 2：覆盖数固定后最大化有效拍照数

```math
\max \sum_{e\in\mathcal P}x_e
```

这一层允许同一拍照目标在不同角度贡献多张照片，因此能体现 60° 冲突图和联合优化的价值。

### Level 3：前两级固定后最大化总安全裕度

```math
\max \sum_e Q_e x_e
```

`Q_e` 为候选任务完整准备窗口上的归一化最小硬约束裕度。

## 为什么不加入任务时间互斥

题面规定的是某项任务执行前需要满足一定时长的运动状态/准备条件，但没有说明这些准备过程必须独占机器人，亦没有给出射击系统与相机之间的资源互斥关系。因此把准备窗口重叠直接设为 `x_i+x_j<=1` 会增加题面不存在的限制。

如后续需要讨论工程实现，可以把“准备资源独占”作为扩展情景，而不作为正式主模型。

## 候选压缩：参考包 5° 方位角箱

为了兼顾 MILP 规模和拍照方向的保真度，正式实现进一步吸收参考包 Q4 的候选压缩方式：

- 射击：每个连续可行段保留首点、末点和安全裕度最大点；
- 拍照：按 **5° 方位角箱**，每个箱保留安全裕度最大的候选，并补充连续可行段端点。

拍照硬约束是 60°，因此用远小于 60° 的 5° 分箱可以显著压缩变量数量，同时避免粗分箱误删临界角度附近的重要候选。

## 连续复核与局部精修

正式实现采用两层连续化处理：

1. 先在 10 Hz 网格做完整准备窗口 rolling-min 可行性筛选；
2. 所有压缩候选在 0.01 s 网格重新检查完整准备窗口；
3. MILP 选出组合后，对每个任务的执行时刻在原候选附近 **±0.1 s** 内做有界一维连续搜索，以完整准备窗口的最小归一化安全裕度为目标；
4. 拍照任务的局部移动只有在仍保持同一目标所有已选照片间至少 60° 时才接受；
5. 最终执行时刻四舍五入到两位小数后，再以 0.01 s 重新核验距离、速度、加速度和拍照角度组合约束。

因此本版将参考包的“5° 角度候选 + 连续局部精修”与本仓库更严格的 0.01 s 完整窗口复核组合起来。

## 基线

采用参考包相同的易解释基线：

> 对每个存在可行候选的目标，独立选择一个安全裕度最大的任务时刻。

该基线天然只能为每个拍照目标选一张照片。MILP 若在一级覆盖数不下降的情况下选出更多满足 60° 要求的照片，即说明二级联合优化有效。

## 主要文件

- `trajectory_state.py`：读取并连续评估问题三固定轨迹；
- `shooting_model.py` / `photography_model.py`：题设硬约束和归一化裕度；
- `feasible_windows.py`：完整准备窗、5° 拍照候选压缩和 0.01 s 连续复核；
- `scheduler.py`：目标覆盖 → 拍照数 → 安全裕度三层字典序 MILP；
- `run_q4.py`：正式入口、±0.1 s 连续精修、基线、扰动检验、Excel 扩展写入；
- `validation.py`：独立重算完整窗口、照片角差、射击唯一性、MILP 状态与模板保护；
- `make_figures.py` / `diagnostics.py`：可适配大量任务记录的正式图件；
- `test_synthetic.py`：无容量、无时间互斥、射击唯一和拍照角冲突合成测试。

正式结果位于 `05_results/q4`。论文与提交脚本会强制检查 `photo_angle_bin_deg=5.0`、连续复核 `0.01 s` 和局部精修半宽 `0.1 s`，从而阻止旧版结果被误用。
